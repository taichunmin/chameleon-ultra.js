# Issue #283: Migrate build from tsup to tsdown

## Decisions

1. **Keep entry filenames unchanged** — `index.js` / `index.mjs` / `index.d.ts` / `index.d.mts` / `index.global.js` (same for `Crypto1` and `plugin/*`), forced via `outExtensions` + `entryFileNames`. `package.json#exports`, `main`, `module`, `browser` stay as-is.
2. **cjs/esm use shared chunks** under `dist/chunks/`; iife is one build per entry (iife can't split).
3. **`stream/web` → `import type`**, runtime reads `globalThis.TransformStream` / `WritableStream` (WebbleAdapter, WebserialAdapter, SlipEncoder). `BufferMockAdapter` (test-only) keeps its real import. Drop `esbuild-plugins-node-modules-polyfill`.
4. **Stop emitting `plugin/SerialPortAdapter.global.js`** (it throws `Class extends value undefined` on load and can't load native bindings). Remove it from the jsDelivr purge list in `ci.yml`. Electron users use the cjs/esm build.
5. `cjsDefault` replaces `build-utils/cjsInterop.ts` (all non-index entries have a single default export); delete the script and `build:cjsInterop`.
6. **Package tests in `.github/workflows/ci.yml`** (`npm-test.yml` merged in and deleted): `yarn build` → `npm pack` → install tarball in a temp project, then:
   - `.cjs` / `.mjs` require/import of `index`, `Crypto1`, every `plugin/*`
   - `tsc --noEmit` on `.cts` / `.mts` fixtures (`module: node16`) incl. `ultra.use(new WebbleAdapter())` (#227)
   - grep that Crypto1's output/chunks don't contain `GET_APP_VERSION`
7. Version bump: done by the user, not in this change.

## Ported settings

`env.VERSION`, `keepNames`, `publicDir` → `copy: 'public'`, `minify` (off in watch), `clean` once, `globalName: 'ChameleonUltraJS'` for iife index, iife bundles all deps.

## Cleanup

Remove `tsup`, `esbuild-plugins-node-modules-polyfill`, and `@microsoft/api-extractor` (if only used by `experimentalDts`) from devDependencies; update `.claude/rules/build-utils.md` / CLAUDE.md mentions of tsup/cjsInterop.

## Follow-ups found during implementation

8. cjs `Crypto1.js` keeps an unused `require()` of the enums chunk (rolldown cjs behavior; `Mf1KeyType` is const-inlined). Accepted: the tree-shaking check walks the import graph only for esm/iife; cjs checks the entry file alone.
9. `keepNames` uses the minifier's `keepNames` (compress + mangle), not rolldown's `output.keepNames`, which made every `.d.ts` import the untyped `rolldown-runtime` chunk.
10. publint (`strict`) and attw (`profile: node16`, entrypoints from `entry`) run via tsdown's options with `enabled: 'ci-only'`, so they run in CI's `yarn build` only. node10 can't resolve subpath exports without `typesVersions` (pre-existing).
